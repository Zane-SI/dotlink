# Dotlink v1 规格

> 术语以 [`GLOSSARY.md`](../../GLOSSARY.md) 为准。设计取舍见 [`docs/adr/`](../adr/)。

## 1. 目标

让一个人在自己的一台公网机器上跑起一套 overlay 网络，把家里的 Mac mini、自己的笔电、手机放进同一个虚拟网段，人在外地时能直接访问家里的 NAS 与局域网服务。同一套东西以 MIT 开源，陌生人能自己部署、自己邀请朋友。

### 非目标（v1 明确不做）

- Exit Node（接管全部出网流量）
- ACL 规则编辑器（v1 单 Network 内默认全通）
- Web 管理台（管理面在 macOS Client 里 + Linux CLI）
- 多 Network / 多用户账号
- IPv6 出站（只发 overlay 内的 IPv6 地址）
- Android 客户端、Linux GUI

## 2. 组件

```
        ┌──────────────┐   HTTPS 8443    ┌─────────────┐
        │ Control Plane│◄────────────────►│    Agent    │
        │  (HTTP+JSON) │  长轮询 Peer Map  │  (每台 Node)│
        └──────┬───────┘                  └──────┬──────┘
               │                                 │
               │ 不在数据路径上                    │ UDP 41641
               │                                 │
        ┌──────▼───────┐                  ┌──────▼──────┐
        │    Relay     │◄────────────────►│  其他 Agent │
        │ UDP / DERP   │   加密报文转发     └─────────────┘
        └──────────────┘
```

三个可执行单元，编译进同一个二进制 `dotlink-server` 的三个子命令（`control` / `relay` / `all`），外加一个 `dotlink-agent`。

## 3. Control Plane

### 3.1 鉴权

- **admin token**：首次启动时生成、打印到 stdout 一次，并存进数据库的 `meta.admin_token`。之后每次启动复用它，不再打印——否则重启一次就把运维锁在自己的 CLI 外面。配置文件里显式给了 `admin_token` 时以配置为准。用于邀请签发、节点列表、Revoke。
- **node token**：Enrollment 时签发，随 Peer Map 的每次请求携带。Revoke 后立即失效。

### 3.2 API

全部 `application/json`，路径前缀 `/v1`。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/v1/admin/invites` | admin | 签发 Invite，返回 token 与二维码 URL |
| GET | `/v1/admin/invites` | admin | 列出 Invite（含是否已用、过期时间） |
| DELETE | `/v1/admin/invites/{id}` | admin | 作废未使用的 Invite |
| GET | `/v1/admin/nodes` | admin | 列出 Node 与在线状态 |
| DELETE | `/v1/admin/nodes/{id}` | admin | Revoke |
| POST | `/v1/enroll` | invite | 用 Invite 换身份 |
| GET | `/v1/map?since=<version>` | node | 长轮询 Peer Map |
| GET | `/healthz` | 无 | 存活探针，200 即就绪 |
| POST | `/v1/candidates` | node | 上报 Candidate；内容变了才推进 map version |
| POST | `/v1/heartbeat` | node | 上报存活，刷新 last_seen（不推进版本） |
| POST | `/v1/routes` | node | 记录本 Node 通告的局域网前缀；空数组即撤销。最多 16 条；成功 204；格式/范围错误 400；与别的 Gateway 冲突 409 |

长轮询本身也是存活信号：两者取更晚的那个，超过 2 分钟没有动静即判离线。Candidate 最多 8 条，`kind` 只允许 `lan` / `stun`——不校验的话，一个 Node 就能把别人的候选列表刷爆。

**签发 Invite**

```http
POST /v1/admin/invites
{}
```
```json
{
  "id": "inv_k3m9q",
  "token": "dlk_inv_7q2m4x9b...",
  "url": "dotlink://enroll?v=1&u=https%3A%2F%2F203.0.113.7%3A8443&t=dlk_inv_7q2m4x9b...&n=home",
  "expires_at": "2026-11-09T08:00:00Z",
  "used_by": ""
}
```

`id` 用于 `DELETE /v1/admin/invites/{id}` 作废；`used_by` 在兑换后填上 Node ID。

Invite 是一次性的、24 小时有效的。兑换成功即标记 `used_by`，重复兑换返回 `409`。

**Enrollment**

```http
POST /v1/enroll
{"invite":"dlk_inv_...","pubkey":"<base64 curve25519>","hostname":"macbook","os":"darwin"}
```
```json
{
  "node_id": "n_7f3a",
  "node_token": "dlk_nt_...",
  "ipv4": "100.64.0.2",
  "ipv6": "fd00::2",
  "network": {"name": "home", "domain": "dotlink"},
  "relays": [{"id":"tx-1","udp":"203.0.113.7:3478","derp":"https://203.0.113.7:8443/derp"}],
  "map_version": 1
}
```

Enrollment 不带 Candidate：真正要公布的是 `dotlink-agent up` 打开的那个端口的映射，Enrollment 时那个 socket 还不存在。守护进程起来后第一件事就是 `POST /v1/candidates`（lan + STUN 映射），之后每 30 秒刷新。

**Peer Map**

`GET /v1/map?since=<version>` 长轮询，最长挂 50 秒。版本没变返回 `204`；变了返回全量。

```json
{
  "version": 42,
  "self": {"node_id":"n_7f3a","ipv4":"100.64.0.2","ipv6":"fd00::2","hostname":"macbook"},
  "network": {"name":"home","domain":"dotlink"},
  "peers": [
    {
      "node_id": "n_1b9c",
      "hostname": "mac-mini",
      "pubkey": "<base64 curve25519>",
      "ipv4": "100.64.0.1",
      "ipv6": "fd00::1",
      "candidates": [
        {"addr": "203.0.113.7:41641", "kind": "stun"},
        {"addr": "192.168.1.10:41641", "kind": "lan"}
      ],
      "subnet_routes": ["192.168.1.0/24"],
      "online": true,
      "last_seen": "2026-11-08T08:00:00Z"
    }
  ],
  "relays": [{"id":"tx-1","udp":"203.0.113.7:3478","derp":"https://203.0.113.7:8443/derp"}]
}
```

v1 每次返回全量，不做增量 diff——单 Network 的规模（个位数到几十台）不值得。

### 3.3 状态

单个 SQLite 文件，三张表：

- `nodes`：Node 身份、Overlay 地址、node token、last_seen、candidates、subnet_routes、revoked。
- `invites`：Invite token、签发与过期时间、used_by。
- `meta`：必须跨重启存活的标量——`map_version`、`next_ip`（地址游标）、`admin_token`、`relay_secret`。

`relay_secret` 是 Agent 与 Relay 之间 HELLO 的 HMAC 密钥。它由 Control Plane 首次启动时生成（也可由配置显式给出），跟着 Peer Map 的每个 Relay 条目一起下发：Node 已经靠 Invite 入网了，再让它抄第二份凭据没有增加任何安全性，只增加了运维负担。`dotlink-server relay` 默认从同一个 DB 里读它。

没有外部依赖，备份就是拷一个文件。

## 4. 数据面

### 4.1 单 UDP socket + 包头分流

Agent 只绑一个 UDP 端口（默认 `41641`），实现 wireguard-go 的 `conn.Bind` 接口。收到的每个包先看 4 字节魔数：

| 魔数 | 类型 | 处理 |
|---|---|---|
| `DLK1` | 探测包（Ping/Pong） | 交给 Hole Punching 状态机，不进 wireguard-go |
| 其他 | WireGuard 报文 | 原样交给 `device` |

探测包用 `nacl/box` 加密，密钥就是 Node 的 Curve25519 密钥对——对端的公钥从 Peer Map 里就有，不需要额外握手。

这样打洞与 WireGuard 共用同一个 NAT 映射，打通的端口立刻就是 WireGuard 能用的端口。

### 4.2 Hole Punching 状态机

每个 peer 一台状态机：

| 状态 | 进入条件 | 行为 | 退出 |
|---|---|---|---|
| `Idle` | 无流量需求 | 不发包 | 有流量 → `Probing` |
| `Probing` | 有流量 / 从 Direct 掉线 | 每 200ms 向该 peer 全部 Candidate 发 Ping，最多 5 轮 | 收到 Pong → `Direct`；5 轮无响应 → `Relayed` |
| `Direct` | 收到 Pong | `SetPeerEndpoint(该 Candidate)`；每 25s Ping 保活 | 连续 3 次无 Pong → `Relayed` + 重新 `Probing` |
| `Relayed` | 打洞失败 | `SetPeerEndpoint(Relay)`；后台每 60s 试一轮 `Probing`，不打断现有流量 | 打通 → `Direct` |

切换发生在 Bind 的发送侧：Backend 每次发往某个 Node 时问一次「现在有没有 Direct 地址」，有就直发，没有就封进 Relay 帧。对 WireGuard 而言 Peer 的 endpoint 始终是 `pk:<公钥>`，**不重握手、不断流**，也省掉每次切换一次 UAPI 往返。等价于 `SetPeerEndpoint`，但不改 WireGuard 自己的配置。

探测包也走这条路径：`DLK1` 魔数的包在 Bind 之前就被摘走，交给状态机；只有 Pong 会推进状态。收到 Ping 一定回 Pong——对方是从我这里拿到地址的，那个地址就是它该打的方向。

### 4.3 Relay

**自有 UDP Relay**：所有帧都是 `[4 字节魔数 DLKR][1 字节 kind][body]`（探测包用 `DLK1`，两者不共用魔数——否则一个 Ping 会被当成 HELLO）。裸的「32 字节公钥前缀」看起来更省，但它有 2⁻³² 的碰撞概率把 HELLO 当成数据包，不值得。

| kind | 帧 | body |
|---|---|---|
| 1 | HELLO | ver(1) + unix(8, BE) + 公钥(32) + HMAC-SHA256(32) |
| 2 | HELLO-OK | unix(8, BE) |
| 3 | DATA | 目标公钥(32) + WireGuard 报文 |
| 4 | ERROR | 错误码(1) + 文字 |

HMAC 覆盖 `ver + 时间戳 + 公钥`，时间窗 ±60 秒，防重放。**发送方的公钥永远不从帧里读**——Relay 按来源地址反查注册表，未注册的地址直接丢包：否则拿到一个 Node 的公钥就能冒充它注入流量。注册表 90 秒静默过期，所以 Agent 每 25 秒重发一次 HELLO；Relay 重启会丢掉整张表，而下一次 HELLO 就把它填回去了——没有握手、没有退避、没有要恢复的状态，这就是全部的重连逻辑。

**DERP 兼容 Relay**：实现 DERP 协议的服务端子集，跑在 TLS 上，路径 `/derp`。`dotlink-server relay -derp :8443 -tls-cert cert.pem -tls-key key.pem` 开启；缺任一文件就拒绝启动——没有证书的 DERP 端点与中间人不可区分。

帧格式照抄上游，为的是让现成的 `derper` 能替换我们自己的服务器：4 字节大端长度（含类型字节）+ 1 字节类型 + 负载。用到的类型是 `ServerKey 0x01`、`ClientInfo 0x02`、`SendPacket 0x03`、`RecvPacket 0x04`、`KeepAlive 0x05`、`Ping 0x0c`、`Pong 0x0d`、`Health 0x0e`、`Restarting 0x0f`，协议版本 2。`ClientInfo` = 版本字节 + 32 字节公钥（就是 Node 的 WireGuard 公钥，Relay 只把它当身份）；`SendPacket` = 目标公钥 + 负载，服务器原样包成 `RecvPacket`（来源公钥 + 负载）转给对端。单帧上限 1 MiB，慢 Peer 的发送队列满了就丢包而不是堵住别人。

**两条 Backend 与切换策略**：Agent 同时持有 UDP Relay 与 DERP 两条连接，`link.Link` 在发送侧选一条。UDP 连续 `FailAfter`（默认 12 秒）没有注册、且 DERP 已注册，就切到 DERP；UDP 一恢复立刻切回，没有停留时间——回来的路永远更快。直连报文永远走 UDP socket：直连路径按定义就是 UDP，DERP 没有打洞这回事。DERP 断开后 `maintainDERP` 每 10 秒重拨，不需要重启 Agent；`-relay-only` 可以完全跳过打洞，适合明知打不通的运营商网络。

一个容易写错的细节：DERP 建连即视为可用（握手完成就置 connected），否则要等满一个 ping 周期才承认自己通了，退路会白白空转 15 秒。

**STUN 复用同一个端口**：Agent 向 Relay 发一个 RFC 5389 Binding Request，Relay 用 XOR-MAPPED-ADDRESS 回答「我看到你的地址是 X」。这不是为了省一台服务器，而是因为**只有同一个 socket 拿到的映射才是打洞能用的映射**——另开一个端口问 STUN，得到的公网地址对应的是另一个 NAT 映射，打过去只会被丢。Agent 每 30 秒刷新一次，映射变了就重新上报 Candidate。

Relay 的选择：v1 只有一个 Relay（配置里写死），Agent 从 Peer Map 的 `relays` 里取。不做就近选路、不做多 Relay 冗余。

### 4.4 MTU

TUN 的 MTU 设为 `1280`。这个值对 IPv6 与多层封装都安全，代价是少量吞吐损失——在「访问 NAS」这个场景里可以接受。TCP 侧做 MSS clamp 到 1240。

## 5. 地址与路由

- IPv4 池 `100.64.0.0/10`，从 `100.64.0.1` 起按索引顺序分配，第 n 台是 `100.64.0.0 + n`，一直发到 `100.127.255.254`（约 419 万台）后报错而不是回绕。
- IPv6 池 `fd00::/64`，第 n 台是 `fd00::n`（十六进制），与 IPv4 共用同一个索引，所以两台地址的编号永远一致。
- 分配游标存在 `meta.next_ip`，删除 Node 不回收地址：地址稳定比省地址重要。
- Agent 往 TUN 里装三条路由：`100.64.0.0/10`、`fd00::/64`，以及每个 peer 的 `subnet_routes`。
- Subnet Router 在自己的 TUN 上开 forward 与 SNAT，把 `100.64.0.0/10` 的源地址伪装成局域网地址转发出去。
- launchd 没有 shell，打包版从 `/usr/local/etc/dotlink/advertise-routes` 读取前缀；`--advertise-routes` 优先于文件。

选 `100.64.0.0/10` 是因为它是 CGNAT 专用段，和绝大多数家宽 `192.168.x` / 企业 `10.x` 不冲突。这也是 Tailscale 的选择，撞了网段排查经验可以直接复用。

## 6. Invite 与 Enrollment 流程

```
Gateway 上的 Client          Control Plane             新 Node
      │                            │                      │
      │ POST /v1/admin/invites     │                      │
      ├───────────────────────────►│                      │
      │◄─── token + QR url ────────┤                      │
      │  显示二维码                  │                      │
      │                            │       扫码 ──────────►│
      │                            │◄── POST /v1/enroll ──┤
      │                            │─── node_token ──────►│
      │                            │◄── GET /v1/map ──────┤
      │◄── Peer Map（多了新 Node）──┤                      │
```

二维码里**只有**控制面地址和一次性 Invite token，没有任何私钥——这点和「二维码 = 一份完整 WireGuard 配置」的常见做法相反，见 ADR-0002 的代价段。

二维码 URL 格式：

```
dotlink://enroll?v=1&u=<control-plane-url>&t=<invite-token>&n=<network-name>
```

## 7. 客户端

三端共用一份 Agent 逻辑（Go），只有「怎么打开 TUN」和「怎么被 UI 指挥」是平台代码。

### 7.1 macOS

- `/Library/LaunchDaemons/com.dotlink.agent.plist`，`KeepAlive`，二进制在 `/usr/local/libexec/dotlink-agent`。
- 用 `utun`（`AF_SYSTEM` / `PF_SYSTEM`），无需任何 entitlement。
- Client（MyGo 菜单栏 App）通过 `/var/run/dotlink.sock`（`root:admin 0660`）指挥 Agent。
- 卸载脚本清理 launchd plist 与 socket。
- 分发：Developer ID 签名 + Hardened Runtime + 公证。

**本地控制通道**（`internal/ipc`）。它是 Unix socket 而不是 TCP 端口：对面那个进程能打开 `utun`、改路由，把这种能力交给「本机任意进程」已经过宽。权限 `root:admin 0660`，而 `admin` 组本来就能装 launch daemon。

| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `/status` | 隧道是否在跑、本机 Overlay 地址、每个 Node 的 `Direct`/`Relayed` 与 RTT |
| POST | `/invite` | 用 Agent 手里的 admin token 签一张 24 小时一次性邀请，返回 `dotlink://` URL |
| POST | `/disconnect` | **停会话不停进程**：拆掉 TUN 与路由，进程留下 |
| POST | `/connect` | 把会话重新拉起来 |

`disconnect` 必须是「停会话」：进程若退出，launchd 的 `KeepAlive` 会立刻把隧道拉回来，按钮就成了谎话。反过来，会话崩溃必须自动重试，否则一个 bug 会让机器整晚离线。两者的区分由 `internal/agent/supervisor.go` 承担——`Stop()` 等 TUN 真正关掉才返回，`Serve()` 只在会话「自己失败」时重启。

Client 不持有 admin token，只拿到签好的短时效 URL：能出二维码的那台机器是 Gateway，其他机器看得到网络但发不出钥匙。

**打包**。`make build` 产出 `bin/dotlink-agent`、`bin/dotlink-server` 与 `bin/Dotlink.app`（`Info.plist` 里 `LSUIElement=true`，不占 Dock）。全部 `CGO_ENABLED=0`：`modernc.org/sqlite` 与 MyGo 都是纯 Go，一个工具链就能出三端二进制。`packaging/macos/install.sh` 装 daemon + App，`uninstall.sh` 清 plist/socket/App 但**保留** `~/.dotlink`（里面是这台机器的身份，删了就要重新入网），`--purge` 才删。

### 7.2 Windows

- Windows 服务 `DotlinkAgent`（自动启动，`LocalSystem`），释放并使用 `wintun.dll`。
- Client（MyGo 托盘 App）通过命名管道 `\\.\pipe\dotlink-agent` 通信。
- 安装器请求一次管理员权限；之后开机自启无 UAC。

### 7.3 iOS

- 主 App（扫码、开关、节点列表）+ `NEPacketTunnelProvider` extension，共享 App Group `group.dev.dotlink`。
- wireguard-go 经 gomobile 编译成静态库，TUN 用 `NEPacketTunnelFlow`。
- `NEDNSSettings` 的 `matchDomains = ["dotlink"]`、`matchDomainsNoSearch = true`。
- 分发：TestFlight（个人开发者账号即可）。App Store 上架被 Guideline 5.4 挡住（VPN 类必须 organization 账号 + D-U-N-S），v1 不做。

### 7.4 MagicDNS

Agent 在自己的 Overlay IP 上监听 `:53`，只回答 `<hostname>.dotlink` 的 A/AAAA 查询，数据来自 Peer Map。

- macOS：写 `/etc/resolver/dotlink`，`nameserver <自己的 Overlay IP>`。
- Windows：`Add-DnsClientNrptRule -Namespace .dotlink -NameServers <自己的 Overlay IP>`。
- iOS：`NEDNSSettings`。

因为解析器监听在 Agent 自己的 Overlay IP 上，这些查询根本不会出 TUN，也不会泄漏给系统 DNS。

实现细节（#6 定案）：

- **名字的来源是 hostname，不是用户填的字段**。`DNSName = Label(hostname)`：取第一个 `.` 之前的部分、转小写、非 `[a-z0-9-]` 的字符折成 `-`、首尾去掉 `-`、截断到 63 字节，空则用 `node`。两端各自算也一致，所以 Peer Map 里同时下发 `hostname` 与 `dns_name`，客户端不必自己实现一遍。
- **重名是错误，不是自动加后缀**。Enrollment 时在同一个事务里比对新名字的 label，撞了就返回 `409 hostname already in use: "mac-mini" is already another Node's name`。自动加后缀会让用户打到一个自己没预期的机器上；被 Revoke 的 Node 不占名字，重装机器不必换名。
- **NXDOMAIN 而不是空答案**：查不存在的名字回 NXDOMAIN，工具立刻失败；回 NOERROR/NODATA 会让 `ssh` 卡在连接超时。名字存在但类型不对（只有 A 却问 MX）才回 NOERROR/NODATA——那是真的「有这个名字，没这种记录」。
- **区域外一律 REFUSED**：Agent 不是互联网的权威服务器，谎称「没有这个名字」会被解析器缓存成事实。
- **TTL 30 秒**：Revoke 之后最多等一个 TTL 就没人再问了；再长会让撤销看起来没生效。
- **解析器规则是可选件**：装不上（没有 root、没有 `/etc/resolver`）只记 Warn，隧道照常跑——为了一个便利功能把网络停掉是本末倒置。`Disconnect` 时先删规则、再关监听。

## 8. 部署

单二进制 + 一份 docker-compose：

```bash
# 单机全包（Control Plane + Relay）
dotlink-server all --config /etc/dotlink/server.toml

# 也可以拆开：一台公网机器跑 relay，家里 Mac mini 跑 control
dotlink-server control --config ...
dotlink-server relay   --db /var/lib/dotlink/dotlink.db -udp :3478
```

`relay` 的密钥默认从 `-db` 指向的库里读（和 Control Plane 同一份），所以两台机器之间不需要手工同步第二份秘密。

```toml
[server]
listen     = ":8443"
tls_cert   = "/etc/dotlink/cert.pem"
tls_key    = "/etc/dotlink/key.pem"
db         = "/var/lib/dotlink/dotlink.db"
admin_token = ""          # 留空则首次启动生成、打印一次并存入数据库

[network]
name       = "home"
ipv4_pool  = "100.64.0.0/10"
ipv6_pool  = "fd00::/64"

[relay]
udp_listen = ":3478"
derp       = true
public_url = "https://203.0.113.7:8443/derp"
```

大陆机器绑域名要 ICP 备案，否则 80/443 会被封——所以默认走 `8443` + Let's Encrypt（DNS-01 或 HTTP-01 到 8443 都行）。证书可以是自签的，但 Client 要能校验，所以推荐 Let's Encrypt。

## 9. 可观测性

- 结构化日志（`slog`，JSON，写 stderr），级别可配。
- `dotlink-agent status` 输出每个 peer 的路径类型、RTT、最近一次打洞结果。
- `dotlink-server doctor` 检查证书有效期、端口可达性、DB 可写、Relay 自连。
- 零遥测。所有诊断信息只在本地。

## 10. 安全

| 面 | 措施 |
|---|---|
| Invite | 一次性、24h、可作废；不含私钥 |
| Node 身份 | 每 Node 一对 Curve25519 密钥，私钥只存本地。v1 存在 `$DOTLINK_HOME/node.json`（权限 0600，与 tailscaled 同做法）；Keychain / DPAPI / iOS Keychain 是加固项，不是 v1 门槛 |
| 控制面 | admin token 与 node token 分离；node token 随 Revoke 失效 |
| Relay | 只按公钥转发，无法解密；Relay 密钥 HMAC 防未授权使用 |
| 探测包 | `nacl/box` 加密，防 off-path 伪造 Pong |
| 本地控制通道 | Unix socket `0660` / 命名管道 ACL，仅本机管理员 |

## 11. 验收标准

v1 完成 = 下面七条全部通过：

1. 腾讯云机器上 `dotlink-server all` 起得来，`/healthz` 返回 200。
2. Mac mini 装 Agent，`dotlink-agent up --advertise-routes=192.168.1.0/24` 后成为 Gateway，通告 `192.168.1.0/24`。
3. macOS Client 点「生成邀请」出二维码，MacBook 扫码入网，`ping 100.64.0.1` 通。
4. iPhone 扫码入网，**关掉 Wi-Fi 走 4G**，`ping 100.64.0.1` 通。
5. iPhone 浏览器打开 `http://192.168.1.10:5000`（NAS 的 Web 后台）能出页面。
6. 用防火墙封掉 Relay 的 UDP 端口，`dotlink-agent status` 在 60 秒内从 `Relayed` 变成 `Direct`。
7. 三端 `dotlink-agent status` 都显示 `Direct`，RTT 与直连基线相差 < 20%。

通告被拒绝时（例如与别的 Gateway 的 409 冲突），Agent 会报错并保持停止，而不是每两秒重试；解决冲突后重新连接即可。

## 13. 已知风险

1. **打洞成功率是二值的**。任一侧是 hard NAT（对称 NAT / CGNAT / 移动网络），基本只能走 Relay。腾讯云 5 Mbps 跑屏幕共享会卡，这是物理限制。
2. **DERP 是 TCP-over-TCP**，单流吞吐有天花板，只能是退路。
3. **「每人自部署」的隐藏门槛**：陌生人需要一台有公网 IP 的机器，并且会跑 docker-compose。
4. **iOS 只走 TestFlight**，公开链接上限 1 万测试者，且 App 不出现在 App Store 搜索里。
5. **单 Relay 是单点**。Relay 挂了，Direct Path 仍可用，但打不通的 peer 会断。v1 接受这个。
