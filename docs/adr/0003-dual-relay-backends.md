# v1 同时做自有 UDP Relay 和 DERP 兼容 Relay

Relay 抽成 `Backend` 接口，v1 交付两个实现：走 UDP 的自有 Relay（低延迟，配合自有探测包），和 DERP 兼容的 Relay（跑在 TCP/443 上）。

## 为什么两个都要

- **自有 UDP Relay** 是 Direct Path 打不通时的默认路径。它和我们的探测包共用一套鉴权与寻址（按目标 Node 公钥转发），可以做端到端的路径质量反馈，延迟也低。
- **DERP 兼容 Relay** 解决的是「UDP 完全不通」的网络。国内运营商对 UDP 限速、丢包、甚至整段封锁都很常见；TCP/443 是唯一稳定的退路。选 DERP 而不是自创一个 TCP 协议，是因为 `derper` 是 BSD-3 开源的、协议有公开实现可对照，意味着使用者可以直接拿一台现成的 derper 接进来，我们也不必从零设计一套抗审查的 TCP 隧道。

## 代价

- 两套转发逻辑、两套鉴权、两套监控。这是 v1 里最容易被低估的一块。
- DERP 是 TCP-over-TCP，单流吞吐有天花板（自建实例约 50 Mbit/s），所以它只能是退路，不能是默认路径。
